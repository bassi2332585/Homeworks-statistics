Point Addition & Doubling Formulas over $\mathbb{F}_p$

Case 1: Point Doubling ($P = Q$)

Tangent slope $\lambda$ requires derivative $\frac{dy}{dx} = \frac{3x_1^2}{2y_1} \pmod p$:

$$\lambda = (3x_1^2) \cdot (2y_1)^{-1} \pmod p$$

Resulting coordinates:

$$x_3 = \lambda^2 - 2x_1 \pmod p, \quad y_3 = \lambda(x_1 - x_3) - y_1 \pmod p$$
Case 2: Distinct Point Addition ($P \ne Q$)

Secant slope $\lambda$ connecting $P(x_1, y_1)$ and $Q(x_2, y_2)$:

$$\lambda = (y_2 - y_1) \cdot (x_2 - x_1)^{-1} \pmod p$$

Resulting coordinates:

$$x_3 = \lambda^2 - x_1 - x_2 \pmod p, \quad y_3 = \lambda(x_1 - x_3) - y_1 \pmod p$$
⚠️ Point at Infinity ($\mathcal{O}$): If $x_1 = x_2$ and $y_1 \ne y_2$ (i.e. $y_1 + y_2 \equiv 0 \pmod p$), or if $y_1 = 0$ during doubling, the line is vertical and the sum is the neutral identity element $\mathcal{O}$. In this toy group, $18G = \mathcal{O}$.

Cryptographic Analysis: One-Way Functions vs. Cryptographic Hash Functions

An in-depth academic synthesis comparing the mathematical foundation of Ethereum's public key generation with cryptographic hashing.

Properties of ECC Scalar Multiplication ($k \mapsto kG$)
  • Elliptic Curve Discrete Logarithm Problem (ECDLP): Given $G$ and $Q = kG$, finding $k$ is computationally intractable for large cyclic groups (e.g., $2^{256}$ in secp256k1). Best known generic algorithm (Pollard's rho) requires $\mathcal{O}(\sqrt{n})$ group operations.
  • Algebraic / Homomorphic Group Structure: Unlike hash functions, ECC scalar multiplication preserves addition:
    (k_1 + k_2)G = k_1 G + k_2 G
    This algebraic linearity enables threshold signatures, ECDSA verification, and BIP-32 deterministic hierarchical wallets in Ethereum.
  • Deterministic & Bijective on Subgroup: For prime order $n$, the mapping $k \mapsto kG$ is a bijection (isomorphism between $\mathbb{Z}_n$ and $\langle G \rangle$). There are zero collisions!
Properties of Cryptographic Hash Functions (e.g., Keccak-256)
  • Strict Avalanche Criterion (SAC): Flipping any single input bit must cause each output bit to flip with probability exactly $50\%$. The relationship between input and output is designed to be purely pseudorandom and structurally destroyed.
  • Arbitrary Input $\to$ Fixed Output: Maps $\{0, 1\}^* \to \{0, 1\}^{256}$. Collisions mathematically exist by the Pigeonhole Principle, but finding one is hard ($\mathcal{O}(2^{128})$).
  • Deliberate Lack of Algebraic Structure: Linear or group homomorphisms are explicitly considered cryptographic flaws in hash functions (e.g., length-extension attacks).
